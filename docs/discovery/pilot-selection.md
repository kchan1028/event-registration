# Pilot selection

Use this sheet to choose the smaller event for the Phase 4 live pilot, and the people accountable for it. Berkeley Omnium is the reference scenario, not the pilot: product.md requires the [first live use to be a lower-risk event](../../product.md#launch-criteria).

Choosing the event now does not commit anyone to it. It tests whether a realistic pilot exists. If no event and organizer are willing, the exit gate is not met.

## What makes a good pilot

| Criterion | Good sign | Warning sign |
|---|---|---|
| Size | One day, one discipline (road race or criterium), modest field | Two-day weekend or a large championship |
| Categories | Some shared fields and at least one junior category, so the pilot tests real rules | Only one open category (proves little) |
| Sanctioning | Clear path to the agreed license and waiver process, or an unsanctioned event if USAC acceptance is not yet in place | Sanctioned event with no accepted process |
| Date | Proposed: at least 4 months after Phase 3 is expected to finish (adjust with the organizer) | Date that forces the schedule |
| Organizer | Willing, available, and able to give honest feedback | Organizer who expects the developer to run everything |
| Fallback | Organizer can switch back to the current provider if the pilot is stopped before opening | No fallback |
| Timer | Willing to test exports before the event | Timer not reachable before race day |

## Accountable people

These names go in the [decision memo](decision-memo.md#team-and-owners) once agreed.

| Role | Responsibility | Agreed by |
|---|---|---|
| Accountable organizer | Owns the event's registration decisions and signs off on Phase 3 rehearsal | Not yet agreed |
| Support owner | Answers registration and check-in failures on opening day and race morning; follows the [operations model](../operations.md) | Not yet agreed |
| Staff using start lists | Can retrieve current and locked start lists and identify revisions | Pending staff rehearsal |
