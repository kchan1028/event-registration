# Pilot run of the usability kit (November 14, 2026)

Status: Pilot only. This is **not** Phase 1 evidence. The tasks were run by an AI coding assistant driving the browser, not by organizers, volunteers, or riders, so nothing here counts toward the 90% unassisted-completion gate. Its purpose was to check that every task can be completed in the current prototype, that the setup steps in [tasks.md](tasks.md) work, and to fix obvious problems before real participants see them.

## How it was run

- Prototype at `origin/main` on November 14, 2026, run locally with a fresh database for each role, as the [setup instructions](README.md#set-up-the-computer-before-each-session) describe.
- Desktop browser window (1024 by 768 pixels), dark theme. Phone-width and daylight checks were not done.
- Every core and optional task in [tasks.md](tasks.md) was attempted, including the setup steps for each role, except the optional daylight task V6.
- Not timed. Check-in speed from this run means nothing, because a script does not hesitate the way a volunteer does.

## Fixed in this change

| Finding | Severity | Change |
|---|---|---|
| In check-in, pressing Enter right after typing or scanning a code did nothing, because the list on screen still showed the previous search. A barcode scanner sends Enter immediately, so scanning would never open the rider. Same for a single name match. | Serious | Enter now looks up the typed text before deciding whether exactly one rider matches ([CheckIn.tsx](../../src/web/CheckIn.tsx)) |
| The rider confirmation for an unreviewed license said "License needs review: not verified yet" with no next step. R4's follow-up asks what the rider would do. | Serious | The item now says to bring the license to the registration desk before racing ([checkout.ts](../../src/shared/checkout.ts)) |
| Every confirmation said "Each entry below lists what is still needed", even when nothing was needed. | Minor | The banner says "Not cleared to race yet" only when something is outstanding, and otherwise says everything is done ([Register.tsx](../../src/web/Register.tsx)) |
| The same-start publish warning joined start group names with "and", and the names themselves contain "and", so it was hard to tell how many groups were involved. | Minor | The warning now gives the count and lists quoted names ([validation.ts](../../src/shared/validation.ts)) |
| "Mark reviewed" stayed disabled with no explanation until the note had 3 characters. | Minor | The button stays enabled and explains what to write ([Registrations.tsx](../../src/web/Registrations.tsx)) |

Each fix was checked again in the browser after the change. Kit changes in [tasks.md](tasks.md): the volunteer setup no longer assumes the example weekend has warnings; it now checks Alex in during setup so V5 works; R3 asks for one parent session without the prefilled demo rider; O1 adds a watch point about finding start groups below the category schedule.

## Watch for in real sessions

Noticed but not changed, because real participants should show whether they matter.

- The rider page says "You qualify" for a category before any license check. R4 tests whether riders read that as "cleared".
- Bundle discounts are split across entries (for example −$5.88 and −$4.12) instead of one "Weekend bundle −$10" line. R2's follow-up should show whether that confuses riders.
- The full-race message says to ask the organizer about the waitlist, but waitlists are not built and no contact is shown.
- In the rider preview, ineligible reasons read "Cat 4 is not one of Cat 3". Watch whether organizers understand it in O3.
- The start-list CSV `rider_id` column holds the order ID. Rider identity across orders is a known gap in [roadmap.md](../../roadmap.md#check-in-prototype); ask the timer whether the column name misleads.
- The start group "Edit" buttons on the race page all have the same name, which is harder for screen-reader users. Note it if a screen-reader participant takes part.

## Not covered

Phone-width sessions, the light theme, daylight readability (V6), keyboard-only use, and everything a real participant brings: hesitation, wrong guesses, and wording they do not understand.
