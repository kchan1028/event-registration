# Chicago Grit

Status: Research case; proposed configuration only. Reviewed November 14, 2026. Edition studied: 2026.

## Published evidence

The [schedule](https://chicago-grit.com/schedule/) describes ten race days. The [July 5, 2026 flyer](https://chicago-grit.com/wp-content/uploads/2026/07/2026-GRIT-Flyer-0705-1.pdf) contains day-specific tables, five-day mini-series, and a ten-pack restricted to categories offered across ten days. Its final-day table places Masters 50/60+ together with separate scoring. Women's combined categories also vary across the program.

The [2026 technical guide](https://chicago-grit.com/wp-content/uploads/2026/07/2026-GRIT-Tech-Guide-0705-1.pdf), printed pages 5-7, distinguishes daily and overall classification treatment and states that riders need not race every day for omnium points/prizes. Therefore an overall-participation rule is not equivalent to purchasing a full-series pack.

The website header now advertises 2027 while linked schedules/guides describe 2026. Use the document's edition, not the site's latest header, as provenance. A day webpage and the final flyer may differ; require reconciliation before publishing a copied day.

## Proposed organizer setup

| Step | Configure | Review boundary |
|---|---|---|
| 1 | One multi-day criterium program with day/venue records | Ten days requires planned support beyond the current seven-day configuration limit |
| 2 | A reusable category library plus explicit availability by date | A five-day category must not be cloned into every date |
| 3 | First-block and second-block start arrangements | Do not turn Cat 2 into Cat 2/3 merely by relabeling the same published category |
| 4 | Explicit daily and overall classification mappings | One entry can have approved scoring tags without another capacity charge |
| 5 | A shared Masters 50/60+ start where approved | Keep the shared limit distinct from separate classifications; confirm who belongs in each age classification |
| 6 | Individual-day selection and approved fixed-race packs | Pack membership depends on category availability; overall eligibility is configured separately |

For the paper exercise, choose the final-day shared Masters 50/60+ row. Create the organizer-approved purchasable option(s), connect them to one start, and map separate classifications as specified by the organizer. The published row alone does not determine whether to sell two categories or one entry with conditional scoring tags. Do not automatically dual-score every older rider.

## Reusable lesson

A series needs date-specific category availability and classification mappings. Repeating a daily template is useful only when overrides are visible. A limited multi-day program and a full-series product can coexist without requiring a complete schedule template for each combination.

## Acceptance exercise

Set up ten dates, omit a five-day category outside its block, and preview a ten-pack only for an eligible full-series category. Preserve separate shared-start classifications and show that a rider buying one day can still follow the published overall-participation rule where allowed. Changing the second block must not rewrite the first. See T03, T04, T09, and T10 in the [case index](README.md#proposed-validation-exercises).

## Open questions

Confirm the final source hierarchy, exact purchasable options under combined rows, age-band versus minimum-age semantics, classifications for juniors inside adult fields, category changes between blocks, and race-specific caps. Current code permits at most seven race days: this is a concrete implementation gap to address deliberately, not a reason to split the event without considering purchase and capacity consequences.
